# 科研选题的审稿式压力测试

## 目的与尺度

站在有建设性的审稿人视角，寻找最可能推翻研究主张或改变决策的缺陷，而不是替候选辩护。按研究阶段和用户要求调整：初步选题聚焦关键假设与可行性，已有结果才讨论证据是否支持主张；用户请求系统审稿时给出完整且有优先级的质疑。不要机械生成固定数量，不因形式上的严格而忽略真正的核心问题。

## 先建立审查对象

用几句话明确研究问题、目标对象与使用条件、候选方法、宣称或预期贡献、已有证据与缺失证据。区分用户已经要求保留的核心价值、可调整实现和尚未决定的选择；将未发生的实验、预测收益、假设案例标明为假设。审查已有论文时以正文及具体版本为准，无法查阅时说清限制；不可把假想结果或实验计划写成现有证据。

## 根据具体候选主动构造质疑

优先选择与主张直接相关、会影响结论的反例和最强近邻。按需检查以下类别，问题必须具体到研究对象与机制，而不是模板式泛问：

1. **问题是否真实且重要：** 困难在哪里、影响谁、何种条件下发生，现有证据是什么？已知观察能否直接支持归因，是否有相反情形？
2. **新颖性与简单拼接：** 最接近工作与候选在问题、数据、机制、监督、假设和评价上具体重合多少？单个构件和完整组合分别是否已有先例？新增价值是否超出换名称、换任务或叠加模块？已知直接先例但未找到实质差异时如实降级，不强造区别；有先例也不自动否定有证据的增量。
3. **必要性与替代方案：** 去掉目标组件、直接使用基础工具、采用固定规则或更简单的方法能否达到同样目标？该组件实际针对什么瓶颈、提供什么独立收益，收益是否包括构建、训练、验证和使用的全部成本？尊重用户硬约束，提出对照不擅自移除。
4. **机制与推断：** 关键中间信号或代理指标真的对应目标结果吗？是否可能仅是相关性、数据选择、规模或其他因素？何种对照或干预可区分替代解释？不要假定指标变化就是任务改善。
5. **可行性与数据条件：** 可获得的数据、标签、环境、接口、算力和时间是否足以执行？关键输入在训练、验证、部署时是否真实可得，跨域、坐标或模态是否匹配？未核实的资源列为待查，而不是预设具备或不可行。
6. **评估和公平性：** 最近邻、简单基线、组件消融、失败案例及多次运行是否覆盖？是否控制数据量、计算、调参、查询预算，避免验证泄漏？模拟或离线指标能否支持真实部署主张？提出与阶段相称的最小实验并解释负结果。
7. **边界与可推广性：** 哪些任务、分布和条件下可能失效？方法是否比基线付出额外代价？不把受控设置、单一任务或原论文的收益直接推广到新场景。

## 每条质疑如何回应

对关键质疑，明确写出：

- **质疑及影响：** 具体漏洞是什么，若成立会否破坏研究的核心价值。
- **当前判断：** 成立、部分成立、不成立或证据不足，并说明依据；既不自动附和也不为了维护方案辩护。
- **已有依据与缺口：** 引用可定位的原始来源或已有真实结果，明确尚未验证的假设；计划实验只是未来检验，不是现有反证。
- **调整和代价：** 有依据时给出最小修改，说明保留了什么、改变了什么、产生什么新条件；已有直接先例且未见增量时降级或回到问题层面重新探索，不能通过增加模块自动消解质疑。
- **关键检验与判定：** 写出最能区分竞争解释的对照、所需数据、支持或削弱思路的可观察结果，以及资源未知时的状态。

回应状态用“已有证据支持 / 可修正但待验证 / 核心假设未验证 / 直接重合且暂未发现增量 / 无法判断”等；它们不是审稿分数或发表保证。对于合理且已解决的质疑，不重复制造新问题；无证据时停止迭代并交付当前最关键的检验动作，不承诺可以回答所有质疑。

## 综合结论

先给是否值得继续及原因，再列最重要的 1–2 项风险、尚缺的关键证据和下一项行动。用户要求详细报告时，再按影响排序展开各项质疑与回应；避免把未验证的设想表述成已经完成的论文贡献。模拟审稿是研究辅助，不能代替对原文、实验和领域专家的核查。
